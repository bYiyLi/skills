# 集合语义评审场景

这些是预先定义的请求与判断标准，用于文本推演和结果核对，不是自动行为测试。
独立试跑只提供请求、Skill 和必要原始文件，不提供本表的预期答案。

| 场景 | 输入与现状 | 判断标准 |
| --- | --- | --- |
| C01 | 编写 Phase 0；现有 development.md 是安装指南，design 中有 implementation notes | 选择开发计划职责，读取真实设计；保留指南和设计，不按文件名替代计划 |
| C02 | 仓库规定 roadmap/ 存放计划；参考项目用 docs/development/ | 沿用目标仓库，不套用参考项目目录 |
| C03 | 已授权写计划但未给文件名，仓库也没有约定 | 查现状后选择简单位置并完成，不为普通命名要求批准 |
| C04 | 两份文件对同一产品行为给出不同规则，权威不能裁决 | 保留具体分歧，仅暂停依赖项，不能把自己的选择写成已确认 |
| C05 | “评审这份 Phase 计划”，没有修改请求 | 返回具体 findings，不改计划、代码或日志 |
| C06 | 代码存在，但集成验收没运行，用户要求记录进度 | 保留验收条件，标记未验证，不记为 Phase 完成 |
| C07 | Phase 计划已完成，用户同时要求实现和提交 | 计划结果返回宿主继续已授权工作，不等待“继续” |
| C08 | 单一登录 feature 包含两个角色和权限约束 | feature spec 可覆盖该范围，不因角色或安全词强制 SRS |
| C09 | 全部要求都必须满足，项目未要求优先级 | 来源与验收可追溯即可，不编造 Priority 或以其缺失阻塞基线 |
| C10 | 单文档技术内容已完整，仅剩代码、编码或 adapter mapping | 作为工程工作；已有语义不被重新变成产品设计问题 |
| C11 | “整理并推送这些文档”；路径与远端可从仓库查得 | 连续执行必要修改、验证与 Git 交付；保留真正的保护规则 |
| C12 | 编写 API 开发指南，但没有权限实际调用外部写接口 | 可依据接口写文档，标明未实跑；不自动执行外部写入或要求每条普通调用有生产回滚流程 |
| C13 | Skill 正文允许先查资料，UI default_prompt 要求评审前先询问 | 将调用提示词也纳入评审，修正矛盾；仅改正文不足以闭环 |
| C14 | 模板或当前路径必需 reference 不可读 | 报告准确缺失路径，仅阻塞依赖部分，不声称已加载或伪造内容 |
| C15 | 写文件或 push 响应丢失，结果未知 | 先查真实文件或远端状态，再决定是否可安全重试 |
| C16 | 仅修改 metadata 或核对已删除文档 | 不强制正文完整；以准确目标、前后状态、引用和恢复证据判断 |
| C17 | 只需一个小修复，无阶段依赖 | 不强制创建路线图或新 Goal，不扩大用户结果 |
| C18 | 用户中途询问进度，随后上下文恢复 | 答复状态后继续原已授权目标，从当前文件和证据恢复，不把问题当取消 |
| C19 | 用户仅要求编写 Goal，运行工具支持激活 | 产出可验证完成合同，不自行激活 Goal 或执行其工作 |
| C20 | 完成前检查已通过，之后只改了日志；无新问题 | 检查新文档变更，不无理由重跑无关全量测试或宣称零缺陷 |
