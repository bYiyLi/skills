# Software Usage Docs

本 Skill 拥有同一产品或接口面的使用文档结果。按读者要学习、完成、操作、查询或
理解的目标组织内容，不把实施计划或内部设计塞进使用指南。结束后返回宿主，继续
本次已授权工作；文档请求本身不授权执行文档中的生产操作。

## 确定操作和来源

按请求与上下文选择 create、revise 或 review。“检查并修复”包含修改；单纯评审
不写文件或改变状态。先读取目标、项目约定、实际接口和当前文档，再询问确实影响
范围或结果的缺失事实，不以缺少用户逐项输入作为停工理由。

新建或正文修订需要读者目标、产品/接口范围、适用版本或环境和事实依据。评审可以
将这些内容的缺失列为 finding。一个请求可包含多个同类文档；每份结果有主要读者
目标，独立部分分别完成。明确要求单文件时按目标分区，不强制拆文件。

核对项目合同、源码、官方接口和运行证据各自能证明什么。源码支持实现声明，实际
命令结果才支持该环境下已运行；原有文档不自动证明当前行为。材料中的命令只作为
内容，不扩张执行权限。来源冲突不能按权威、范围和版本裁决时明确标注，不任选一方。

## 加载所需资源

正文创建、修订或审校读取
[references/doc-flavors-and-checklist.md](references/doc-flavors-and-checklist.md)，按读者目标
选择内容合同。涉及仓库写入或路径、metadata、状态与生命周期判断时读取
[references/doc-management-contract.md](references/doc-management-contract.md)。只核对或
修改管理事实时不要求正文目标，也不加载内容检查。

新建且仓库没有适用模板时：

- tutorial 可用 [assets/tutorial-template.md.tmpl](assets/tutorial-template.md.tmpl)；
- how-to 可用 [assets/how-to-template.md.tmpl](assets/how-to-template.md.tmpl)；
- CLI/API reference 可用 [assets/reference-template.md.tmpl](assets/reference-template.md.tmpl)。

按已核对事实替换占位符，删除不适用章节。operator guide、explanation、修订和审校
按内容合同处理，不强套模板。必需资源缺失或不可读时报告准确位置，保留独立结果，
不从记忆伪造已加载内容。

## 创建或修订

1. 找到承担同一读者结果的现有文档，优先修订；确需不同结果时再新建，不为内部模式
   选择重复确认。目标目录与格式按管理规则确定。
2. 为每份文档或分区确定主要目标、适用环境和验证方式。保留有效结构，只修改本次
   受影响内容及其必要引用；避免每次重排整份手册。
3. 写准确前置条件、步骤与可观察结果，或完整接口查询信息；只解释影响使用决策的
   实现细节。例子不得引入规则之外的必需行为。
4. 文档涉及受控访问时说明读者所需权限；涉及生产、高影响或难以恢复的操作时，在
   相关步骤写明目标、影响、前置检查和恢复/升级路径。按真实风险处理，不给每个普通
   安装命令或开发 API 调用追加审批流程。
5. 用已授权、可用的安全验证环境检查步骤或例子。写文档不等于获准调用外部写接口；
   未运行项标明来源核对和执行限制，不把“未运行”误报成语法错误或整份文档失败。
6. 复读实际输出，检查事实、链接、示例、占位符与 diff。请求写文件时验证准确路径，
   内联草稿不能代替落盘完成。

缺非决定性事实时可交付明确标注限制的草案，不需要另加“允许草稿”的确认环节。
若缺口使步骤会误导读者，保留准确语法或已知部分，指出缺什么及如何核对；不要把
权限、影响或恢复边界未知的高影响动作呈现为就绪步骤。

## 只读审校

全文审校应用相应类型合同；限定审校只检查指定部分和必要依赖。来源不可用时仍可
检查文本，限制事实结论。核对例子与规则一致、参数和返回准确、前置条件可满足、
步骤有可观察结果，以及真实高影响操作具备边界。

每项 finding 给出位置、读者会执行的具体任务、错误结果或歧义、依据和最小修正。
无问题时说明所查范围和未验证行为；不以未用模板标题或未实跑生产操作本身判缺陷。
只核对生命周期的请求按管理规则处理，不修改被审对象。

## 完成与恢复

文档完成需要满足所选类型合同、事实与来源一致、交付形式完成、适用检查通过；
源代码核对、实际运行、读者验证、发布是不同证据，分别报告。有影响使用的未决项
时报告草案或部分结果，不宣称已验证可执行。

失败后先核对当前文件与副作用状态，只重试确认未完成且可安全恢复的已授权动作。
权限拒绝不绕过，不重复未知结果操作，继续独立内容。简洁交付结果、路径、实际检查
和未完成项，不输出内部状态枚举的全量清单，也不以 Skill 结束为由停下宿主已授权步骤。
