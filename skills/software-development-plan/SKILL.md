# Software Development Plan

本 Skill 拥有开发计划的创建、修订和只读评审结果。计划完成后回到宿主，继续同一任务
已经授权的实现、验证或 Git 交付；用户仅要求计划时到计划为止。

## 判断请求与来源

从当前请求和上下文判断 create、revise 或 review。“检查并修复”包含修改；只读评审
不写计划或日志。读取适用仓库指令、文档入口、同类计划、所属需求/设计和当前 Git 状态。
用户提供了文件位置时核对其职责；未指定路径不等于缺少写入授权。

先用已有材料确定目标、范围和设计输入。不要让用户重新确认已有决定，也不要把未实现
误报成未设计。没有设计文档但目标已足够明确的小任务，可以直接计划；没有足够目标时
只询问会改变交付物或验收的问题，不为编写计划虚构产品规则。

正文创建、修订或评审前读取
[references/plan-contract.md](references/plan-contract.md)。涉及仓库写入、路径或生命周期
判断时，读取 [references/doc-management-contract.md](references/doc-management-contract.md)。
必需资源不可读时报告准确路径，只暂停依赖部分，不声称该部分已经应用规范。

## 选择计划层级与位置

- 单一任务只需一个计划，不强拆 Phase。
- 有真实依赖或可独立验收的阶段时，用总计划记录顺序、依赖和阶段状态，用 Phase
  文档记录该阶段的实施和验收。总计划链接详情，避免两处维护完整清单。
- 优先更新已有同主题计划，保留其有效结构和稳定任务标识；不创建平行真源。
- 遵循目标仓库的计划目录和模板。没有适用约定时，可选择
  `docs/development/README.md` 和 `docs/development/phases/NN-topic.md` 作为本次布局，
  并说明该选择；这是可调整默认值，不是所有仓库的规定。
- `docs/development.md` 等名称本身不能证明文档是计划。开发者安装、运行和调试步骤
  属于使用指南；设计中的 implementation notes 属于技术方案；日志属于历史记录。
  错放内容在获准整理范围内迁移并修复引用，保留已确认规则与历史证据。

新建且仓库没有模板时，总计划可使用
[assets/roadmap-template.md.tmpl](assets/roadmap-template.md.tmpl)，Phase 或单一实施计划可使用
[assets/phase-plan-template.md.tmpl](assets/phase-plan-template.md.tmpl)。修订不重套模板。
模板字段来自已核对目标、设计、任务和验证证据；删除不适用章节，完成前移除所有占位符。

## 创建或修订

1. 核对本次结果及其设计来源，记录会影响执行的当前状态和实际依赖。
2. 把范围拆成能交付并验收的工作项；给出关联设计、交付物和执行顺序。不要把命令清单
   或文件目录当作完整计划，也不要为尚未要求的未来能力增加阶段。
3. 为每项交付物写明可观察的验收条件及验证方式，覆盖集成和仓库必需检查。
   尚不存在的命令标为待建立，不伪造已运行结果。
4. 写明评审范围、发现问题后的修复与复验，以及阶段完成条件。把工程选择交给执行者；
   仅将会改变产品约定、权限或验收且现有证据无法裁决的选择留给用户。
5. 修订进度时保留原有验收要求，依据实际实现、运行和评审证据更新。不能把计划写完、
   代码存在或部分测试通过直接记成 Phase 完成。
6. 写入后复读、检查 diff、链接、任务与验收覆盖和状态一致性。总计划同步阶段摘要；
   技术决定写回设计真源，日志只记录本次变化。

来源冲突先按权威、适用范围和当前版本核对。仍有分歧时标出具体受影响工作项，继续
独立部分；不要将整个计划或已确认设计退回“未设计”。计划可以带未决依赖完成编写，
但必须区分“计划已交付”和“所有工作已可执行”。

## 只读评审

按请求范围检查计划与设计、实现状态、验收和证据的对应关系。范围未限定时覆盖整个
计划；缺少实现证据不妨碍检查计划文本，但限制进度结论。发现问题时给出位置、具体
会遗漏或误判的工作、依据及最小修正，不因缺少模板标题而判定内容缺失。

特别核对：交付物无验收、依赖顺序错误、计划重新发明设计、日志冒充当前状态、验收
条件被改弱、检查结果属于旧代码、总计划与 Phase 状态冲突。没有发现问题时说明已审
范围和未验证部分，不把文本评审写成实现通过。

## 结束与恢复

交付计划内容、文件修改或只读结论时，简洁报告结果、位置、验证和真正阻塞项。修改、
验证、实现完成、提交、推送是不同事实，分别需要证据。

执行失败后先检查实际文件状态，保留已完成部分；只重试确认未完成且可安全重试的
已授权动作。真实拒绝不绕过。若规则导致暂停，引用准确来源及相关原文，说明受影响
动作，继续独立工作；本 Skill 不增加逐项批准或“继续”确认节点。
