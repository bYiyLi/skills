# Software Development Plan

拥有请求范围内的计划结果，不因编写计划启动实现。交付后返回宿主继续同一请求已授权的工作。

## 确定范围与来源

从请求和上下文判断创建、修订或只读评审；评审不写文件或日志。读取适用仓库指令、
当前 Git 状态、已有同主题计划及本次需求/设计来源。先查已有决定，只有仍会改变范围、
交付物或验收的未决选择才询问。目标已明确的小任务不以缺少独立设计文件为阻塞。

正文操作读取 [references/plan-contract.md](references/plan-contract.md)；写入或判断路径、
状态、移动和归档时读取 [references/doc-management-contract.md](references/doc-management-contract.md)。
仅检查管理事实时不要求完整计划正文。必需资源不可读时报告准确路径，只暂停依赖部分。

## 先确定计划单元，再组织实施阶段

**实施计划**是有界范围、独立跟踪状态和自身完成条件的计划单元；在 roadmap 中承担
一个 Phase 时称为 **Phase Plan**。**内部阶段**是单元内的步骤或工作项分组，可以有
顺序依赖、局部测试和局部验收。**Roadmap**协调多个计划单元的目标、依赖、状态与链接。

1. 先根据用户范围和已有计划确定本次处理几个独立计划单元。明确“只有一个开发计划”
   时保持一个单元；未指定且没有独立完成边界的依据时，按一个单元组织。
2. 只有需要分别维护范围、状态和完成结论的工作才考虑独立计划；局部可测试、可 review
   或被后续步骤依赖，都不足以单独决定拆分。独立计划可以并行，不必互为前置输入。
3. 再判断是否需要新 roadmap。一个计划不为索引新建 roadmap；已有 roadmap 或仓库明确
   要求入口时保留并同步摘要。本次只做 Phase 05 不等于整个项目只有一个计划。
4. 最后安排每个计划内部的阶段和文件布局。计划单元数、内部小节数和 Markdown 文件数
   分别判断，不从模板名或目录反推计划数量。

例如“一个脚手架重构计划，内部按 Template → init → upgrade → release validation 实施”
对应一个实施计划、四个内部阶段，不对应四个 Phase Plan。

用户否定当前数量、层级或文档职责时，暂停基于该判断的结构性写入，回读规则与现状。
约束已明确且修正仍在原授权内时直接修正；只有仍存在实质分歧才询问，不固定追加审批。

## 选择位置与模板

优先修订已有同主题真源，保留有效结构和稳定任务标识。用户目标、仓库规则及适用惯例
优先于默认布局。没有约定时，单一计划可用 `docs/development/phases/NN-topic.md`；
需要多计划总览时再用 `docs/development/README.md`。这些是可调整默认值。

安装、运行和调试指南不因名为 development 就成为计划。获准迁移时修复引用并保留
历史证据。普通命名不需批准，改变计划范围或既有职责的未决选择不能当成普通重命名。

新建且仓库没有模板时，可用 [assets/phase-plan-template.md.tmpl](assets/phase-plan-template.md.tmpl)
编写单一实施计划或 roadmap 中的 Phase Plan；资源名不要求拆 Phase。
总览可用 [assets/roadmap-template.md.tmpl](assets/roadmap-template.md.tmpl)。修订不重套模板；
按已核对输入填充，删除不适用章节和占位符。

## 编写、更新与评审

把范围组织成工作项，关联设计输入、依赖、交付物、可观察验收及验证方法。覆盖必要
集成检查和评审修复后的复验；尚不存在的命令标为待建立。计划引用技术决定，不另造设计。
未决依赖注明受影响工作；允许交付带缺口的计划，但不能声称全部工作已可执行。

更新进度时保留原验收，用当前实现、检查和评审证据判断完成。计划写完、代码存在、
局部测试通过或已提交，均不单独证明计划范围已实现。Roadmap 只同步摘要和链接。

评审按指定范围和必要依赖检查工作、设计、依赖顺序、验收、状态和证据；未限定时覆盖
整个计划。每项发现给出位置、可达误判、依据和最小修正。文本评审不证明实现通过。

写入后复读并检查 diff、链接、任务与验收覆盖及状态一致性。失败后先检查实际文件，
只重试确认未完成且可安全恢复的已授权动作，保留独立结果；权限拒绝不绕过。
报告结果、位置、实际验证和剩余缺口，分别说明修改、实现、提交与推送事实。规则导致
暂停时引用准确来源和相关原文，区分规则与自己的解释。
