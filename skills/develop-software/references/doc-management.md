# Document files and lifecycle

Use for document writes, mechanical edits, path/metadata/lifecycle inspection or
authorized management. Document lifecycle metadata is distinct from implementation
progress, which uses the planning route. Pure path/metadata checks need no body
audit; content changes follow the documentation and type routes in SKILL.md.

## Locate and preserve the owning file

Inspect repository instructions, entrypoints, generators, current files and source
ownership. Reuse an adequate same-topic source without asking again merely to
choose revise over create. Follow the user's path, repository conventions, then
a simple non-overwriting location. Resolve consequential conflicts over ownership,
published entrypoints, compatibility links or retention; absent conventions alone
are not a blocker. Do not change an ownership map to justify a desired placement.

Keep established formats and fields; add no frontmatter, owner or approval state
without a consumer. Ordinary document maintenance covers necessary links and
supported metadata within the authorized file scope. Writing a document does not
approve its content or establish implementation/release. Protected states need
their actual entry evidence and authority.

Authorized moves/archives update references and preserve required history.
Deletion additionally needs authorization for the actual targets and checks of
references, retention and recovery. An already-deleted document is assessed from
its prior identity and current Git/reference evidence; expected absence is not
missing input. Cross-document decisions use the main synchronization route.

## Verify the requested file state

For read-only path/link or lifecycle checks, inspect existing sources and targets
without writes. Distinguish inaccessible evidence from confirmed missing or
case-mismatched local links. For writes, reread saved output and inspect actual
changes and affected local links/casing,
placeholders, examples and status relationships; do not audit unchanged examples
for a metadata-only task. In Git run `git diff --check` and inspect new
files separately; otherwise compare available prior evidence and report limits.
For metadata/path-only work, ensure unrelated body content is unchanged. Verify
state values and evidence, both ends of moves, archival/deprecation records, and
actual deletion/reference cleanup as applicable.

After failure or uncertain writes, inspect current files before retrying only
confirmed incomplete safe actions; preserve concurrent edits and independent
results. Report actual persistence separately from a proposal or rendered draft.
