### 分析与修改

| 范围 | 检查结果与处理 |
| --- | --- |
| 文档分类 | 缺少开发计划，导致 Phase 工作容易落入设计或 how-to；加入独立类型与选择边界 |
| software-development-plan | 新增 capability；创建、修订、评审路线图/Phase，区分设计输入、工作项、验收、评审、状态与证据 |
| requirements | 简单 feature 因角色/安全词强制升级 SRS，Priority 缺失也可阻塞基线；改为按实际范围与约束选择，优先级按需 |
| design | 保留视图与设计驱动检查，明确已确认语义与剩余工程工作的区别；删去重复的通用失败/生命周期分支 |
| usage | 保留读者目标和接口事实合同；依据真实操作影响定义权限/恢复说明，不把普通开发步骤当生产审批 |
| 仓库文档管理 | 普通新路径和派生 metadata 不再被当作用户保留决定；保留正式批准、破坏性操作与工具权限 |
| sync | 接入计划类型；文档行级授权核对不再意味着逐行询问，保留上游依赖与部分失败处理 |
| prompt / skill authoring | 区分 Skill 职责终点和宿主任务终点；先查可用输入；核对独立调用提示词和生成模板 |
| Codex 调用 metadata | 两个 default_prompt 仍要求评审前询问，与正文冲突；改为沿用当前任务模式与授权 |
| Goal | 检查了定义、完成证据、修订和激活边界；现有职责成立，保留正文与 metadata |
| Nexum | 保留 Web 专属执行边界；补齐计划与指南的区别及阶段验收证据；不把该环境强加给本地 Codex |
| 测试与 CI | 由 Nexum 单包检查扩展为集合格式、资源、调用 metadata、链接和新计划模板检查 |

五个独立文档包各保留一份相同的管理规则，以支持单独分发；不建立跨包文件依赖。
项目原有目录优先；开发计划的路径只是无既有约定时的默认选择。没有将 KGOS 或
Lithograph 的特定目录、状态、技术栈变成通用产品要求，也没有改变现有许可。
